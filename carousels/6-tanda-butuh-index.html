DATABASE TIPS
6

tanda database kamu
butuh index.

Biar lo nggak stuck di masalah yang sama
kayak kebanyakan developer.

Geser
02 / 10
Masalah

Index itu kayak daftar isi
di buku

Tanpa index, database harus baca seluruh buku
buat cari satu kalimat. Dengan index, langsung lompat.

Tanpa daftar isi, lo harus baca semua halaman
03 / 10
Tanda #1

Query SELECT ambillama

Query yang dulu cepet sekarang jadi lambat — padahal nggak ada code change.

slow-query.log
-- Query ini ambil 3.2 detik SELECT * FROM orders WHERE user_id = 1234 AND status = 'pending'; -- Expected: < 50ms -- Actual: 3200ms
Catatan
Kalau query mendadak lambat, cek index-nya.
04 / 10
Tanda #2

EXPLAIN nunjukin full table scan

Jalanin EXPLAIN di query lo. Kalau type-nya "ALL" — database baca semua baris.

EXPLAIN output
EXPLAIN SELECT * FROM orders WHERE user_id=1234; +----+------+-------+--------+ | id | type | key | rows | +----+------+-------+--------+ | 1 | ALL | NULL | 98432 | +----+------+-------+--------+ type=ALL → full table scan! rows=98432 → baca semua baris, nggak ada index
Catatan
Type "ALL" = full scan. Tambah index di kolom WHERE.
05 / 10
Tanda #3

CPU usage naik drastis
pas query jalan

CPU spike tiap kali heavy query jalan? Database kebanyakan cari data.

htop
PID USER %CPU COMMAND 1234 mysql 98.7 mysqld 5678 node 12.3 node 9012 root 0.3 bash -- MySQL pake 98% CPU! -- Query tanpa index = full scan -- Full scan = CPU kerja overtime
Catatan
Full scan = CPU kerja lebih keras dari seharusnya.
06 / 10
Tanda #4

Sering dapat timeout errors

Connection timeout, query timeout —
semua bisa jadi simptom database keberatan.

Error yang sering muncul
● Lock wait timeout exceeded
● Deadlock found when trying to get lock
● Statement cancelled due to timeout
Yang harusnya terjadi
Query selesai dalam hitungan milidetik, bukan detik.
07 / 10
Tanda #5

JOIN antar tabel makin lambat

Tabel makin besar, JOIN makin lama.
Tanpa index, JOIN harus scan dua tabel sekaligus.

Foreign Key = wajib di-index
Kolom yang dipake buat JOIN antar tabel harus punya index. Tanpa itu, setiap JOIN scan dua tabel sekaligus.
08 / 10
Tanda #6

Data makin banyak,
makin lambat

100 baris cepet. 10.000 mulai lambat. 1.000.000? Lambat banget.

Polanya jelas
Kalau performa makin buruk seiring data nambah — itu bukan bug, itu kurang index.
09 / 10
Solusi

Gimana cara tambah index

1
Jalanin EXPLAIN
Cek type "ALL" atau "index" di output EXPLAIN.
2
Tambahin index
CREATE INDEX di kolom yang sering di-WHERE atau JOIN.
3
Cek lagi
Jalanin EXPLAIN lagi — type harusnya berubah jadi "ref" atau "range".
10 / 10
Wrap Up

Index = performa naik,
user senang

Jangan nunggu user komplain soal lambat.
Cek EXPLAIN lo sekarang.
