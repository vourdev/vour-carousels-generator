MASALAH

Webhook
Terlihat Simple

Setup awalnya mudah. Tapi di production, banyak yang bisa salah.

Provider timeout 5 detik. Kalau lambat, retry.
03 / 08
KESALAHAN #1

Retry Tidak Ditangani

Server down sebentar = webhook hilang selamanya.

// Webhook handler — no retry logic app.post('/webhook', async (req, res) => { await processPayment(req.body); res.sendStatus(200); // ↑ if processPayment fails, // provider already got 200 // → webhook is LOST forever });
Catatan
Return 200 dulu, proses di background.
04 / 08
KESALAHAN #2

Verifikasi Signature Dilewat

Tanpa verifikasi, siap saja bisa kirim webhook palsu.

// Attacker sends forged webhook app.post('/webhook', (req, res) => { // ❌ missing: verify signature await grantAccess(req.body.user); res.sendStatus(200); }); // Anyone can call this endpoint // with a fake payment event
Catatan
Validasi HMAC signature sebelum proses.
05 / 08
KESALAHAN #3

Response Diblock

Query lambat bikin webhook timeout. Provider anggap gagal.

// Webhook handler — sync DB call app.post('/webhook', async (req, res) => { const user = await db.find(req.body.id); // ↑ takes 3-5 seconds... // provider timeout = 5s // → retries = DUPLICATE res.sendStatus(200); });
Catatan
Proses async, return 200 dulu.
06 / 08
KESALAHAN #4

Tidak Idempoten

Webhook dikirim ulang = data diproses dua kali.

// Webhook fires twice (provider retry) // Both requests hit your server: // Request 1: POST /webhook await db.insert('orders', order); // ✓ // Request 2: same payload await db.insert('orders', order); // DUP! // Result: customer charged twice // Fix: check if order exists first
Catatan
Cek event_id sebelum insert.
07 / 08
SOLUSI

4 Best Practices

Checklist untuk webhook yang reliable.

  • ✓ Handle retries — gunakan queue, bukan sync handler
  • ✓ Verify signature — validasi HMAC sebelum proses
  • ✓ Process async — return 200 dulu, handle di background
  • ✓ Idempotent — cek event_id sebelum insert

TAKEAWAY

Webhook Reliable
Itu Bisa

Retry, verify, async, idempotent. Simpan 4 ini.
